# Causa's data

## What it is

A synthetic wholesale distributor, 1995 to 1997, in two separate source systems:

| Source | Zetaris data source | Tables | Rows |
|---|---|---|---|
| ERP (orders and master data) | `causa_erp` | `region` 5 · `nation` 25 · `customer` 1,505 · `part` 400 · `supplier` 60 · `orders` 40,661 · `lineitem` 142,597 | 185,253 |
| CRM (account management) | `causa_crm` | `accounts` 1,505 · `account_events` 921 | 2,426 |

The ERP follows the [TPC-H](https://www.tpc.org/tpch/) schema (a subset of its columns); the region and nation names are TPC-H's. Every row is generated by [`scripts/generate-data.ts`](../scripts/generate-data.ts) from a fixed seed (`20261025`), so every clone gets byte-identical data. It is not TPC-H `dbgen` output and contains no real companies or people.

## Why synthetic, and what is planted

Revenue-variance questions need a ground truth to check the agent against. Three business stories are planted in the data. The agents are never told about them and have to find them through SQL:

1. **Germany, Q3 1996:** three large automobile-segment accounts lose an annual fleet-parts tender to a cheaper competitor and stop ordering at the end of June (CRM: `contract_ended`, preceded by `complaint` and `tender` events).
2. **France, Q1 1997:** a winter volume-discount programme adds 8 points of discount; more units are sold at less revenue per unit (CRM: `price_renegotiated`).
3. **United States, 1997:** two machinery customers won in December 1996 start large monthly orders (CRM: `new_contract`).

Everything else is background: Pareto-sized customers, seasonality, and random CRM meetings, complaints, renewals and support events. A question about any other country or period (for example Japan, Q2 1996) has no planted cause, which makes it a useful control.

## Files

| File | Used by |
|---|---|
| `docker/initdb/01_erp.sql.gz`, `02_crm.sql.gz` | The `causa-db` Postgres container loads these on first start (one database per source) |
| `data/seed/causa_seed.json.gz` | `SAMPLE_MODE=true`: the same rows, loaded into in-memory SQLite. Input data only, never answers |

## Load it into Zetaris

```bash
docker compose up -d          # starts causa-db on the Zetaris network and loads both databases
npm run zetaris:register      # runs scripts/register_zetaris_sources.sql against Zetaris
```

Registration is automated: the script creates the `causa_erp` and `causa_crm` data sources, registers their tables, and finishes with a federated query that joins CRM events to ERP customers.

## Regenerate

```bash
npx tsx scripts/generate-data.ts
docker compose down -v && docker compose up -d   # reload the databases from the new files
```
